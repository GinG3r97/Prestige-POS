# Yosef POS Audit — 2026-05-21

Generated from four parallel audits (security, bugs, DB persistence, integration). Severity:
- 🔴 **CRITICAL** — fix before any pilot
- 🟠 **HIGH** — fix before broader release
- 🟡 **MEDIUM** — integration gaps & data quality
- 🟢 **LOW** — polish & nice-to-have

## 🔴 CRITICAL — must fix before pilot

### 1. Printer / reprint / refund / email buttons are all no-ops
- **Files:** [lib/features/orders/orders_view.dart:495,513,531](lib/features/orders/orders_view.dart#L495)
- **Issue:** `Reprint receipt`, `Refund`, `Email receipt` are all `onPressed: () {}` — empty handlers. Tender success path also never calls `PrinterService`, so even brand-new orders never print to the LAN ESC/POS printer despite the whole `lib/features/printing/` module being built.
- **Impact:** The printer module is a paperweight. Refunds can't be issued. Reprints don't work.
- **Fix sketch:** Wire `PrinterService.sendBytes` into the tender success flow + the reprint button. Build a Refund flow that updates `orders.status = 'refunded'`, refunds the payments, and writes an audit_log entry. Email receipt either via Supabase Edge Function + a transactional email provider, or hide the button until built.

### 2. PIN verify can be brute-forced across employees
- **File:** [lib/app/app_state.dart:1027-1095](lib/app/app_state.dart#L1027)
- **Issue:** `verifyPin()` iterates `_employees` and on a Postgrest error (including lockout) silently continues to the next employee. An attacker can probe many PINs against many employees without ever triggering the visible lockout state.
- **Impact:** 5-attempt lockout is defeated — attacker has effectively `5 × employee_count` tries before any wall.
- **Fix sketch:** Match the cashier on the entered PIN first (or send the entered PIN to a single RPC that figures out which employee). Don't iterate and swallow errors. Surface lockout state to the UI.

### 3. `lockSession()` doesn't clear permission cache
- **File:** [lib/app/app_state.dart:3847+](lib/app/app_state.dart#L3847)
- **Issue:** When the user taps Lock, `currentStaff` is cleared but `_employeeRoles`, `_employees`, and the derived `currentPermissions` stay cached. After another cashier PINs in, `currentPermissions` is **stale from the previous user** until something else triggers a re-hydrate.
- **Impact:** Cashier could briefly access routes they shouldn't (or vice versa) right after unlock. Privilege check leaks across users on a shared device.
- **Fix sketch:** In `lockSession()`, also clear roles/permissions; on PIN unlock, re-fetch the staff's role from DB before computing permissions.

### 4. `product-images` storage bucket is public
- **File:** `supabase/migrations/20260520140000_products_image_url_and_storage_bucket.sql:9-42`
- **Issue:** Bucket is `public = true` with SELECT allowed for any authenticated user. Folder structure is `tenant_id/...` — anyone with a Supabase session can enumerate other tenants' product images.
- **Impact:** Cross-tenant data leak. Product catalogs and pricing imagery exposed.
- **Fix sketch:** Make the bucket private. Serve via short-lived signed URLs (`createSignedUrl`) or a tenant-scoped Edge Function proxy. Update `ProductImageField` and any image-rendering widget to ask for signed URLs.

### 5. Stopping a session orphans the charge
- **File:** [lib/app/app_state.dart:2342](lib/app/app_state.dart#L2342) (`stopSession`)
- **Issue:** Sets the booking to `status=completed` with a calculated `price_cents`, but **never creates an order or pushes the charge to the cart**. Customer leaves, cashier has no receipt path, the charge is invisible to Sales/Reports.
- **Impact:** Active Sessions is a beautiful UI that doesn't produce revenue records. Sales reports miss session income entirely.
- **Fix sketch:** On `stopSession`, automatically add a session line to the cart and open the tender sheet — OR insert an order row server-side with the session's totals and a `session_id` link.

### 6. Three migrations applied via MCP are not in the repo
- **Missing files in `supabase/migrations/`:**
  - `members_and_plans` (members + member_plans tables)
  - `payroll_persistence` (time_entries + payroll_runs + payslips)
  - `bookings_open_sessions` (nullable `ends_at` on bookings + open-session unique index)
- **Impact:** A fresh checkout cannot reproduce the live DB schema. New devs / branches break. Branch deploys via Supabase CLI miss these tables.
- **Fix sketch:** Run `supabase db diff` (or pull the schema) and commit the missing SQL files into `supabase/migrations/` with proper YYYYMMDDHHMMSS prefixes.

## 🟠 HIGH — fix before broader release

### 7. `verify_cashier_pin` RPC missing inner auth check
- **File:** `supabase/migrations/20260520023436_employees_roles_cashier_pins.sql:217`
- **Issue:** `SECURITY DEFINER` function checks tenant ownership via `p_tenant_id` (which is client-controlled). No explicit `auth.uid()` ownership check inside.
- **Impact:** If a session token leaks, attacker can verify PINs across any tenant they own.
- **Fix sketch:** Add `IF NOT EXISTS (SELECT 1 FROM tenants WHERE id = p_tenant_id AND owner_id = auth.uid()) THEN RAISE...` at the top of the function. Also `SET search_path` on every SECURITY DEFINER function.

### 8. `updatePayslip` called without `await`
- **File:** [lib/features/payroll/payroll_view.dart:798](lib/features/payroll/payroll_view.dart#L798)
- **Issue:** Returns `Future<String?>` (null = success). Caller discards both the await and the error string. Edits can silently fail.
- **Fix sketch:** `await` the call, on error show `PushToast` with the message + revert the local change.

### 9. NPE risk on `state.tenant!`
- **Files:** [lib/features/dashboard/dashboard_view.dart:240](lib/features/dashboard/dashboard_view.dart#L240), [lib/features/pin/set_pin_view.dart:111](lib/features/pin/set_pin_view.dart#L111), and several other `state.tenant!` sites
- **Issue:** Tenant becomes null on session drop / multi-tenant switch. `!` operator crashes the frame.
- **Fix sketch:** Replace `tenant!` with null-safe access (`?.businessName ?? 'Your store'`) or guard the whole widget with `if (state.tenant == null) return _ConnectingView();`.

### 10. Failed PIN value briefly visible in widget tree
- **File:** [lib/features/login/login_view.dart:76-99](lib/features/login/login_view.dart#L76)
- **Issue:** On failure, error message is shown before the `pin = ''` reset in setState. Capturable via Flutter inspector on debug builds.
- **Fix sketch:** Clear the PIN buffer BEFORE rendering the error. Use `setState` with both updates in one cycle.

### 11. Money rounding via floating point loses centavos
- **File:** [lib/features/products/products_view.dart:1916](lib/features/products/products_view.dart#L1916)
- **Issue:** `Money((pesos * 100).round())` — `0.1 * 100 = 10.0000…1` etc. Off-by-one centavo bugs on small price deltas.
- **Fix sketch:** Take cents directly via a `KeyboardAccessoryField` parsed as cents. Or use `(double.parse(text) * 100).toInt()` after multiplying via a known precision (e.g. `(pesos * 1000).round() ~/ 10`).

### 12. DateTime comparisons skip `.toLocal()`
- **File:** [lib/features/bookings/bookings_view.dart:415,104-106](lib/features/bookings/bookings_view.dart#L415)
- **Issue:** UTC-stored timestamps compared against `DateTime.now()` (local) without converting. Bookings render in wrong timeslot in non-UTC timezones.
- **Fix sketch:** Always call `.toLocal()` when reading from DB; same on order/booking/session display layers. Add a helper `toLocalDay(DateTime t)`.

## 🟡 MEDIUM — integration gaps & data quality

### 13. Members aren't usable at checkout
- **Files:** `lib/features/sell/`, `lib/features/tender/`, `lib/features/cart/`
- **Issue:** Members are a roster-only view. No way to attach a member to an order; hour balance + day-pass counts are tracked in the model but never deducted at checkout. The tender sheet shows "Bill to member" but it's locked/disabled.
- **Fix sketch:** Add a "Member" chip on the Sell page that opens a member picker. Once selected: deduct hours from a running session, count one day-pass per booking/session, apply plan perks. Persist via `members.units_remaining -= consumed`.

### 14. Bookings can't actually be charged
- **Issue:** `bookings.price_cents` is set but no path from "Confirmed booking" → tender flow. Bookings are effectively free in production.
- **Fix sketch:** Add a "Charge customer" button on the booking detail sheet that pushes a line into the cart with `category=bookings`, opens tender, and on success links the booking to the resulting order.

### 15. Reports never auto-refresh
- **File:** [lib/features/reports/reports_view.dart](lib/features/reports/reports_view.dart)
- **Issue:** Loads once on init. Placing an order in another tab/device doesn't refresh.
- **Fix sketch:** Add a periodic refresh on the active lens (every 30s) or use Supabase realtime subscriptions on `orders`.

### 16. DB errors leak schema in debug builds
- **File:** [lib/app/app_state.dart:443,1319](lib/app/app_state.dart#L443) and other debugPrint sites
- **Issue:** Postgrest exceptions (with constraint names, table names, SQL state) printed when `kDebugMode`.
- **Fix sketch:** Strip the message before logging or only log a generic "DB write failed" + short error code.

### 17. Most numeric `TextField`s have no input formatter
- **Files:** Many in `lib/features/products/`, `lib/features/maintenance/`, `lib/features/inventory/`
- **Issue:** `keyboardType: TextInputType.number` accepts `-`, `+`, letters via hardware keyboards or paste.
- **Fix sketch:** Propagate the `moneyInputFormatters` / `wholeNumberInputFormatters` pattern we added to KeyboardAccessoryField. Sweep all forms.

### 18. `firstWhere(orElse: dummy)` returns dummy with empty id
- **File:** [lib/features/members/member_form_dialog.dart:117](lib/features/members/member_form_dialog.dart#L117)
- **Issue:** When lookup fails, caller may get back a `Member(id: '')` and call ops on it.
- **Fix sketch:** Use `firstWhereOrNull` from `collection` package + explicit null check.

### 19. `printer_configs` table exists but no AppState cache
- **Issue:** UI reads/writes directly to DB. Printer list won't auto-update across devices without a manual refresh.
- **Fix sketch:** Add `_printerConfigs` field + `restorePrinterConfigs()` in `_restoreTenantFromDb`. Add `addPrinter`/`updatePrinter`/`removePrinter` mirroring the bookable_resources pattern.

### 20. Inventory recipe deduction has no rollback
- **File:** [lib/features/tender/tender_sheet.dart:800](lib/features/tender/tender_sheet.dart#L800)
- **Issue:** Local cache deducts pre-RPC. If RPC fails after local deduction succeeds, inventory cache is stale.
- **Fix sketch:** Deduct only AFTER `create_paid_order` RPC returns success. Or re-fetch inventory on RPC error.

## 🟢 LOW — polish & nice-to-have

- Onboarding doesn't seed a default member plan → empty Members tab on first run.
- Sparse PushToast triggers: no low-stock toast, no expiring-member toast, no stale-session toast (>6h), no failed-PIN toast.
- Settings page has many `_comingSoon()` handlers — feels broken.
- PIN entry fields don't set `obscureText: true` explicitly — visible during entry.
- `audit_log` has no explicit DENY policy for DELETE/UPDATE — relies on RLS being enforced.
- AnimationController `forward()` calls in pin/set_pin_view.dart not guarded by `mounted`.
